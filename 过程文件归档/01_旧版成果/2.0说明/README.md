# 识生

**先记住这一组。有余力，再继续。**

给辅导员用的看图速记工具：第一次就把学生照片与完整考核信息一起记，再通过口答留下需要复习的内容。单文件、本地运行，无需账号或服务器。

下载 [shisheng.html](https://github.com/9562721-pixel/shisheng/raw/main/shisheng.html)，用 Chrome 或 Edge 打开。`index.html` 与下载版由同一份源码生成，内容相同。

## 怎么练

1. 导入学生照片文件夹。第一次核对不确定的词条，之后直接使用本机照片副本。
2. 一组六人，逐人完整看照片、姓名、班级、籍贯、贫困情况、心理关注。**学号不背。**
3. 这一组看完后，遮住信息回忆；揭晓后点选漏答或答错的项。
4. 每位学生每轮最多追加一次回忆，并尽量隔开两人；轮末来不及安排的留待下次。可以选择“先放一放”，继续接触其他学生。
5. 未看过、看过轮次较少的学生优先。选择“再看没记住的”可单独补漏；刷新或离开页面后可以继续。

顺序、乱序和班级范围都可选择。所有照片保持完整比例，不进行变形或趣味加工。

## 五人模考

从可用名册或所选班级中随机抽取五人，不足五人时取全部。支持“只报姓名”“只报班级”“完整信息”，三种回答范围分别记录。

**不计时，不推算正式分数。**结果显示本轮答对人数与漏项。口答由使用者自己对照评定，无录音或语音识别。

## 文件名

```text
班级_姓名_学号_贫困_心理_籍贯_.jpg
```

- 贫困、心理空白分别表示“非困难”“无关注”，学习时需要回答。
- 文件名写了“否”，仍按原文显示，不能当作肯定状态。
- 学号用于关联更新记录，不显示在学习答案中。
- 不符合六段格式、出现不认识的标签、必要字段缺失或学号重复，会进入核对，确认前不出题。
- 核对时可编辑各字段原文；不会自动生成学生信息。
- 支持 JPG、PNG、WebP、GIF、BMP，跳过隐藏文件和 `__MACOSX`。

## 照片与进度

- 导入时生成最长边 720 像素的本机 JPEG 副本，原文件不变。
- 重新打开使用本机副本，不自动扫描原文件夹。
- 不同照片库分别保存进度；另一届学生请“导入新的照片库”。
- 当前照片库变化时使用“更新照片”，查看导入报告后再确认替换。
- 原文件路径相同或唯一学号相同的记录会关联；答案与文件时间/大小都未变化时保留进度，否则重新学习。
- 导入失败会逐文件列出；更新时读取失败的旧记录暂时保留。缺失于新文件夹的记录会在确认后移出当前库。
- **清理浏览器数据、换浏览器、变更访问地址可能无法找到旧数据。**请导出备份后再操作。
- 备份包含照片、词条、当前练习与成绩；恢复时新建独立名册，不覆盖已有名册。备份文件上限 250 MB / 2000 人。
- 这是本地版本，设备间不会自动同步。可通过备份文件在设备间转移。

如果在原地址更新旧版本，会尝试迁移 `shisheng-folder` 中的照片与词条，旧数据库不修改。旧版熟练度保留为历史记录，不直接算作新版完整口答成绩。

## 开发

源文件和构建脚本统一在 `过程文件归档/02_构建脚本/`，单文件产物在根目录。该目录的 `src/demo.json` 保留旧版演示素材。

```sh
cd 过程文件归档/02_构建脚本
npm install
npm run build
npm run verify
```

- `npm run build` 同时生成 `index.html`、`shisheng.html`，无运行时外部依赖。
- `npm run verify` 使用本机 Chrome 与 Playwright，通过虚构照片验证六人学习、模式隔离、刷新恢复、300 人导入、备份和旧数据迁移。过程材料写入 `过程文件归档/01_验收预览`（可以设置 `SHISHENG_VALIDATION_DIR`）。
- `npm run verify:edges` 检查重复学号隔离、空名册、更新与损坏备份等边界。

不将真实学生照片或备份提交到仓库。
